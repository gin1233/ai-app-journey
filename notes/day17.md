## Embedding 是什么

**一句话**：
向量化，讲文本内容，user request content全部向量坐标化，通过计算坐标位置远近来判断相关性
**举例**（把三句话变成数字，说明"意思近 = 数字近"）：
真好（1.1，2.1，....，512）
真棒（1.2，2.2，....，512）
## 为什么数字能表达意思

**用"意思坐标"解释**（二维地图上的猫/狗/玫瑰）：
猫
(0.9, 0.2)
狗
(0.9, 0.5)
老虎
(0.9, 0.9)
玫瑰
(0.1, 0.2)


**为什么是 512 维而不是 2 维**：

因为2维过于单调，比如以人为例子，人的attribute就很多喜好，肤色，穿着，....这些2维不足以cover

**⚠️ 一个反直觉的事实：单个维度有意义吗**：

没有任何意义，一个维度不代表一种attribute

**所以应该看什么**：

看整体看相似度

## 余弦相似度

**类比（两个人走路方向）**：

| 相似度 | 含义 |
|---|---|
| 1 | 相似甚至重合 |
| 0 | 垂直没有关系 |
| -1 | 背离 价格与需求 |

**为什么只看方向，不看长度**（举个"语气强度"的例子）：

你超级宇宙无敌帅 vs 你真帅

**⚠️ 实践数据：真实的文本相似度大概在什么范围**：
| 关系 | 典型相似度 |
|---|---|
| 同义句 | **0.85 ~ 0.95** |
| 相关但不完全 | 0.5 ~ 0.8 |
| 弱相关 | 0.3 ~ 0.5 |
| 无关 | **0.1 ~ 0.3** |
## 为什么需要向量索引

**5000 个块要算多少次**：
5000 次 × 512 维 = 256 万次乘法
**100 万个块呢**：
1m 次 × 512 维 = 1b 次乘法
**索引用图书馆类比怎么理解**：

根据类型分类方便查找IVFFlat
问路 HNSW
**⚠️ ANN 是什么意思，为什么能接受**：
Approximate Nearest Neighbor
牺牲一点精度换取速度的极致提升


## 动手的五个步骤

| 步骤 | 为什么要这一步 |
|---|---|
| ① 换镜像 | 官方 PostgreSQL 镜像里没有 pgvector |
| ② 启用扩展 |PostgreSQL 默认不认识 vector 这个类型。 |
| ③ ALTER TABLE 加列 | create_all 不会给已存在的表加列 |
| ④ 回填向量 | 库里已有的块还没有向量。 |
| ⑤ 语义搜索 |搜"怎么配置数据库连接"，看谁能排第一 |
