## RAG 的秘密：把资料塞进 prompt

**普通 prompt 和 RAG prompt 的差别**（用自己的话）：

普通考记忆回答 会瞎编
rag会参考文档 减少幻觉 没有就说回答不了

**贴一段你实际用的 RAG prompt**：
1. 只根据【参考资料】里的内容回答
2. 如果资料里没有答案，就说"资料里没有相关内容"，不要编
3. 引用资料时，在句末标注编号，比如 [1]
4. 不要使用资料之外的知识
**为什么说"RAG 不神秘，难的是找得准"**：

## 三条约束防幻觉

| 约束 | 防的是什么 |
|---|---|
| 只根据资料回答 | 拿训练记忆"补充"资料里没有的东西 |
| 没有就说没有 | 模型硬编一个看起来合理的答案 |
| 标注来源编号 | 用户无法核对答案真假 |

**⚠️ 这三条 100% 有效吗**：
模型有时候还是会"发挥"
## 引用编号

**为什么要在 prompt 里给每块编号**：
让模型引用	让它写"根据资料 [1]"
让用户核对	用户能看"这条答案是从哪来的"
**⚠️ 模型标的 [1]，一定对应你心里的那块吗**：
它只是"照着你给的格式"写的。
**所以返回里必须带什么**：
所以你要在返回里把 sources 一起带回去，让前端能显示真实的出处。
## 拒答

**用户问"红烧肉怎么做"，系统该怎么办**：
去参考相似度
**代码是怎么判断的**：
最高相似度选项里均低于最低相似度 拒答
**⚠️ 阈值为什么要实测**（结合你 Day 17 的数据说）：
阈值决定了拒答的标准 每个模型的embedding 是不一样的所以没有通用标准 自己测最准 防止出现幻觉或者全部拒答的情况

## 拼 prompt 时，编号要注意什么
你必须保证"返回给用户的 sources"和"prompt 里的编号"完全一致。
**为什么两处都要用 `enumerate(..., start=1)`**：
保证编号从 1 开始且顺序一致。
**如果两处不一致会怎样**：
如果两处用不同的遍历方式，编号就会错位 —— 用户点开 [1]，看到的可能是另一段。

 - 如果检索到 5 块，但只有第 5 块是对的，模型会用上吗？
 不一定。而且有个专门的研究结论。
现象：Lost in the Middle（迷失在中间）
2023 年有个研究，把正确答案放在长上下文的不同位置，看模型能不能找到：
准确率
  ↑
  │ 高 ██                      ██ 高
  │    ██                      ██
  │    ██    ██          ██    ██
  │    ██    ██          ██    ██
  │    ██    ██    ██    ██    ██
  └────┴─────┴─────┴─────┴─────┴──→ 位置
      开头   中前   中间   中后   结尾
              ↑
          这里最差
结论：信息放在开头和结尾，模型记得最牢；放在中间，最容易漏。
这个现象叫 "Lost in the Middle"。
你的情况：第 5 块正好在最后
好消息：最后一位属于"效果好"的那一侧（U 型曲线的右端）。
坏消息：它是分数最低的一块，模型会"默认"它最不重要。

| 做法 | 说明 |
|---|---|
| **① 按分数排序**（你已经是） | 最相关的放最前 |
| **② 减少 top_k** | 5 → 3，噪音少 |
| **③ prompt 里加一句** | "以下是 5 段资料，**都可能有部分答案，请逐一检查**" |
| **④ 上 Rerank** | 用更准的模型重排，让真正相关的浮上来 |
